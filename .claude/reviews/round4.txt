## Findings

### Medium — Asset response failures change exit code with the output destination

WHAT: The same insecure redirect or HTTP 404 exits 1 with --output - but exits 5 when writing to a file. A loopback probe reproduced both differences. Response validation is not a transport failure, and automation cannot rely on an exit code that changes solely because output moved from stdout to a file.

WHERE: The file path catches fetchDownload, response validation, body streaming, and filesystem work together at src/commands/download-asset.ts:63, then maps every otherwise-unclassified error to transport exit 5 at src/commands/download-asset.ts:150. The stdout path performs response validation outside its stream catch at src/commands/download-asset.ts:136. Existing redirect rejection coverage only exercises stdout at test/assets.test.ts:154.

WHAT GOOD LOOKS LIKE: Under the stable exit-code contract in README.md:108, redirect and HTTP response errors must retain the same classification for file and stdout output; only deadlines are exit 4, transport/stream interruptions exit 5, and file I/O exits 6. Add file-output assertions to the existing download security integration rather than creating another test.

### Medium — API deadlines after response headers return invalid-response exit 1

WHAT: When an API server sends HTTP 200 headers and a partial JSON body but stalls until --timeout expires, the CLI returns invalid_response with exit 1. A loopback probe using --timeout 0.1 --json projects list reproduced this. The timeout contract requires exit 4 across the complete request, including body consumption.

WHERE: The timeout signal is created and retained only inside sendRequest at src/api/get-api-response.ts:59. Body parsing occurs later at src/api/get-api-response.ts:97, where every JSON read failure becomes invalid_response without checking whether the deadline expired. The core-family integration contains no post-header deadline case at test/core-resources.test.ts:37.

WHAT GOOD LOOKS LIKE: Under the stable timeout exit-code contract in README.md:108, the request deadline must cover headers and response-body consumption. Preserve enough timeout state to classify a body abort as exit 4. Per the lean-test directive, add one correctness-critical post-header timeout assertion to the existing core/API family integration.
