Findings

High — Video-list response validation remains narrower than the public route schema.

- WHAT: The CLI parses `videos[].createdAt` with `z.iso.datetime()`, while the current public route response schema declares `z.string()`. A server-valid string can therefore be rejected as `invalid_response`.
- WHERE: `src/commands/run-videos.ts:16`. The source contract is `/Users/mike/Code/viewpress/src/app/api/v1/videos/route.ts:22`.
- WHAT GOOD LOOKS LIKE: Under the exact-response-schema rule, parse `createdAt` with `z.string()`. The current handler may continue returning ISO strings and the docs may describe that current behavior, but the CLI boundary must not narrow the declared public schema. Do not add a response-variant microtest.

Medium — Help and version do not obey the documented global-option placement contract.

- WHAT: Documentation says every global option may appear before or after a command. `--help` and `--version` are not removed or normalized by global parsing, so `viewpress projects list --help` and `viewpress projects list --version` both return usage exit `2`.
- WHERE: `src/cli/parse-global-arguments.ts:14`, `src/cli.ts:41`, `docs/commands.md:3`, and `README.md:92`.
- WHAT GOOD LOOKS LIKE: Under help/runtime consistency, either make help and version genuinely global at documented positions or narrow the documentation to their actual supported placement. For ergonomic CLI behavior, a leaf `--help` should show relevant command usage and global `--version` should print the version. Do not add help-parser microtests under the lean-test rule.

Low — Materially long parsers and validators remain outside the previously refactored territory.

- WHAT: Several functions still combine option scanning, mutable parsing state, validation, and result construction across roughly 44–87 lines.
- WHERE: `src/commands/run-images.ts:79` (`getImageOptions`), `src/commands/run-images.ts:193` (`getValidatedImageOptions`), `src/commands/run-video-generation.ts:258` (`validateVideoGenerationInput`), and `src/commands/run-voices.ts:75` (`getVoiceOptions`).
- WHAT GOOD LOOKS LIKE: Under the short-function rule, apply the existing command-local input/reader/validation pattern without adding a shared parser framework or trivial abstraction layer.
